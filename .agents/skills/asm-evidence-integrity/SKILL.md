# ASM Evidence Integrity & Provenance Guardrails (`asm-evidence-integrity`)

## Purpose
This skill enforces cryptographic tamper evidence, strict data classification, and audit provenance across all telemetry, observations, findings, and risk assessments in Attack Surface Monitor (ASM).

## Mandatory Data Classification Standards
All data presented in the system or returned by APIs MUST be explicitly classified:
1. **FACT**: Directly observed scanner output (e.g. HTTP response header, TLS certificate fingerprint, DNS A record).
2. **INFERENCE**: Algorithmic derivation based on facts (e.g. detected technology stack based on header pattern).
3. **ASSUMPTION**: Expected default organizational policy configuration.
4. **DECISION**: Recorded security decision or exception logged by an authorized human operator.
5. **RECOMMENDATION**: Suggested remediation action generated by the risk engine.
6. **AI HYPOTHESIS**: Response generated by the AI assistant (`/assistant`). MUST NEVER be treated as authoritative scanner fact.

## Provenance Pipeline
```
Raw Observation
  → Evidence Hashing (SHA-256)
  → HMAC Signature (Tamper Evidence & Authenticity)
  → Ingestion & Derivation
  → Risk Evaluation
  → Finding Generation
  → Operator Decision / Remediation
  → Automated Scan Verification
```

## Terminology & Cryptographic Rules
- **Cryptographic Terminology**: HMAC-SHA256 signatures provide **integrity**, **authenticity**, **provenance**, and **tamper evidence**. Do NOT describe HMAC as providing cryptographic non-repudiation (non-repudiation requires asymmetric digital signatures).
- **Raw Evidence Monospace Formatting**: Raw evidence payloads, hashes, certificate fingerprints, and HTTP headers MUST be formatted in 13px monospace blocks.
